Empty vs. error vs. no access

Denne demo viser samme kontekst — Filer i Villa Solbakken — i fem tydeligt forskellige states: loading, empty, filtered, error og no access. Formålet er at undgå, at tomme lister, fejl og adgangsbegrænsninger blandes sammen.

designregel

Årsagen styrer UI’et

Hvis der ingen data er, hjælper vi brugeren videre. Hvis filteret skjuler data, nulstiller vi filter. Hvis noget fejler, tilbyder vi retry. Hvis adgang mangler, forklarer vi det roligt.

Beslutningsflow

Praktisk flow til udvikling og komponentlogik.

  1. Loader data stadig?

    Vis loading eller skeleton.

  2. Fejlede datahentning?

    Vis error state med retry.

  3. Mangler brugeren adgang?

    Vis no access eller restricted state.

  4. Findes der data, men ikke med aktuelle filtre?

    Vis filtered/search empty med nulstil-handling.

  5. Findes der ingen data?

    Vis empty/first-use/context empty med næste naturlige handling.

Beslutningstabel

Samlet differentiering mellem state-typerne.

State Betydning Primær handling Visuel tone

Filtered Data findes muligvis, men ikke med aktuelle filtre Nulstil filtre / ryd søgning Neutral og forklarende
Error Noget gik galt Prøv igen Tydelig fejlmarkering
