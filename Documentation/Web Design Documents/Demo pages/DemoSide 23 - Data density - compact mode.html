Data density / compact mode

Denne demo viser tre density levels: comfortable, default og compact. Tæthed ændrer spacing, metadata-prioritering og antal synlige handlinger — men må ikke reducere accessibility, touch targets eller forståelighed.

Compact må ikke bruges til kritiske beskeder

Upload mislykkedes

Filen er for stor. Vælg en mindre fil, og prøv igen. Denne type besked skal være læsbar og må ikke gøres for kompakt.

density rule

Undgå compact på kritiske flows

Confirmations, no-access, errors, onboarding og destructive actions skal bevare tydelighed, spacing og læsbarhed.

Mobil compact reducerer information — ikke touch targets

accessibility

Compact må ikke bryde baseline

  • Touch targets skal stadig være store nok.
  • Focus states skal stadig være tydelige.
  • Labels og statusbeskeder må ikke skjules.
  • Farve må ikke blive eneste signal.

Density som tokens

Density bør styres med tokens/classes, så spacing ændres konsistent på tværs af komponenter. 

:root {
  --card-padding: 1rem;
  --row-padding-y: .75rem;
  --table-cell-padding: .75rem;
}

[data-density="comfortable"] {
  --card-padding: 1.5rem;
  --row-padding-y: 1rem;
  --table-cell-padding: 1rem;
}

[data-density="compact"] {
  --card-padding: .75rem;
  --row-padding-y: .45rem;
  --table-cell-padding: .5rem;
}
