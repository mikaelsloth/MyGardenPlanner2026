Navigation state og return-flow

Denne demo viser hvordan MyGardenPlanner bevarer brugerens arbejdskontekst: URL-båret liste-state, returnUrl, specifikke tilbageknapper, status efter retur, highlight af nyt/ændret objekt, tabs som URL-state, preview-state og edge case hvor nyt indhold ikke matcher aktive filtre.

4. Edge case: nyt element matcher ikke aktivt filter

Planten er oprettet

Den vises ikke i listen, fordi det aktuelle filter er “Sol”, og planten er oprettet med “Skygge”.

filtered empty after create

Vigtigt UX-princip

Hvis appen bare returnerer til listen uden forklaring, kan brugeren tro at oprettelsen fejlede. Derfor skal UI’et forklare, at elementet findes, men ikke matcher de aktive filtre.

8. Anchor-baseret return frem for pixel-scroll

bedre ved dynamiske lister

Returnér til objekt-id

For lange eller virtualiserede lister er det mere robust at returnere til et konkret element end til en pixelposition.

/planter?search=lavendel&highlight=plant-123&returnTo=plant-123
mindre robust

Pixel-scroll alene

Pixel-scroll kan fejle, hvis billeder loader langsomt, rækkernes højde ændrer sig, eller listen får nye elementer.

scrollTop = 1847px

9. Modal/drawer vs. fuldt sideflow

kort handling

Brug modal/drawer

Upload fil, invitér kunde eller hurtig opret kan ske uden at forlade siden. Scrollposition og listekontekst bevares naturligt.

lang handling

Brug fuld side med return context

Længere planteformularer, haveformularer og materialeredigering bør have egen side, men kende deres returnUrl.

10. Hvad gemmes hvor?

Søgning/filter/sortering Ændrer hvilket indhold brugeren ser. URL query
Aktiv tab Repræsenterer ofte en meningsfuld sektion på detail page. URL/query
Pagination Brugeren skal kunne vende tilbage til samme side. URL query
View-mode Kan være side-state eller brugerpræference. URL / local storage
Scrollposition Gendannes ved return-flow, hvis indholdet stadig findes. Session/browser
Anchor/highlight-id Robust ved lange, dynamiske eller virtualiserede lister. URL/query
Sidebar collapsed Layoutpræference, ikke sideindhold. Local storage

Beslutningspunkter

  • Brugeren skal tilbage til samme arbejdskontekst efter opret, rediger, upload eller preview.
  • Liste-state bæres i URL’en, når den ændrer hvilket indhold brugeren ser.
  • Return-flow bruger specifik tilbageknaptekst, fx “Tilbage til plantelisten”.
  • Efter return vises rolig inline status, så brugeren forstår at handlingen lykkedes.
  • Nyt eller ændret objekt highlightes kortvarigt, hvis det findes i den aktuelle visning.
  • Hvis objektet ikke matcher filteret, forklarer UI’et hvorfor og tilbyder en relevant handling.
  • Tabs og preview kan være URL-state, hvis de repræsenterer en meningsfuld visning.
  • Store lister bør bruge anchor-id frem for ren pixel-scroll, når det er muligt.
