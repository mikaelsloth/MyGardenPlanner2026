Toasts vs. inline statusbeskeder

Denne demo viser, hvornår feedback bør være persistent og kontekstuel som inline statusbesked, og hvornår en kort toast er nok. Hovedreglen er: vigtig information skal kunne genlæses.

hovedregel

Toast må kun bruges til det, brugeren trygt kan overse

Fejl, no-access, validation, uploadproblemer, destructive actions og return-flow bør være inline.

Situation Toast Inline Bemærkning
